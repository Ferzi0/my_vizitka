# Сайт-визитка: Эдуард Торгашов (Ferz)

Одностраничный сайт разработчика сайтов, Telegram-ботов и веб-сервисов. Статические HTML, CSS и немного JavaScript без фреймворков и сборки. Тема «ход ферзя»: разделы страницы — ходы, ферзь движется по доске вместе с прокруткой. Палитра осенняя, бордовая, меняется по сезонам.

## Запуск локально

```bash
cd ferz-site
python3 -m http.server 8000
# http://localhost:8000
```

Через npm (удобно и для телефона, и для проверки формы):

```bash
brew install php          # один раз
npm start                 # сайт с PHP на порту 8080; адреса для телефона печатаются в консоли
npm run mail              # показать последнее «отправленное» письмо
```

Это `tools/dev/php-server.sh`. Телефон должен быть в той же Wi-Fi сети. Остановка: Ctrl+C; порт меняется так: `PORT=8081 npm start`. Сервер отдаёт только файлы сайта и `send.php`: служебное (`send.config.php`, `.git`, `*.md`, `src-images`, `tools`) закрыто. Настоящих писем он не шлёт: функция `mail()` подменена «почтовой ловушкой», и каждая заявка складывается в `.dev-mail/` (в `.gitignore`) как `.eml` и читаемый `.txt`. Так проверяется всё, кроме доставки до реального ящика: приём формы, проверки, защита, готовый текст письма. Нужен `send.config.php` с адресом получателя (образец: `send.config.example.php`); для отладки удобно поставить `rate_max` побольше (по умолчанию 3 заявки за 10 минут с одного IP), на хостинге верните 3. Без PHP сайт можно смотреть и так: `python3 -m http.server 8000`, форма тогда уходит через почтовую программу.

Страницы открываются и двойным кликом (`file://`), но шрифты браузер при этом может не подгрузить, и форма сразу пойдёт через почтовую программу.

## Структура

```
index.html, privacy.html     страницы
css/main.css                 дизайн-система (токены, сезоны) и стили; css/privacy.css
js/theme-init.js, js/main.js тема без мигания; прогрессия, меню, форма, аналитика-слот
send.php                     приём заявок с формы на хостинге с PHP
send.config.example.php      образец настроек (копия send.config.php создаётся на сервере)
.htaccess, _headers          заголовки безопасности: Apache и Netlify/Cloudflare Pages
assets/                      иконки, og-image.jpg, шрифты (woff2 + лицензии OFL),
                             assets/works/ — сжатые скриншоты работ (AVIF, WebP, JPG; 800 и 1600 px),
                             assets/portrait/ — вырезанный портрет (AVIF, WebP, PNG с прозрачностью)
src-images/                  исходные скриншоты работ (PNG) и src-images/portrait/ — оригинал фото
                             (не в git и не на сервере)
tools/                       set-domain.sh, package.sh, minify.sh, images.sh, portrait.sh (+ portrait/cutout.m)
ANALYTICS.md                 как подключить приватную аналитику
STATUS.md                    история этапов, проверки, долг (на сервер не выкладывать)
```

## Что заполнить перед публикацией

Заглушки на сайте помечены `[ЗАПОЛНИТЬ]` (пунктирная плашка).

1. **Почта** (`hello@example.com`): контакты, подвал, форма, `js/main.js`, `privacy.html`.
2. **Telegram:** ник и бот подставлены (`t.me/ferzV1`, `t.me/ferzV1bot?start=site`). Если бота переименуете, поправьте ссылку в `index.html` (в формате `https://t.me/<username>?start=site`, без `@`).
3. **GitHub** и **сертификаты:** ссылки в блоке стека.
4. **FAQ:** ответы про предоплату и про права на код. Условия назвать нужно вам.
5. **Домен:** `sh tools/set-domain.sh ваш-домен.ru` подставит его в canonical, Open Graph, JSON-LD, sitemap и robots. Сначала можно добавить `--dry-run`.
6. **Фото:** уже на первом экране (вырезанный портрет). Заменить — см. «Портрет на первом экране» ниже.
7. **Политика конфиденциальности:** проверьте обязательства в `privacy.html` (хранение, удаление, аналитика) и подтвердите их фактическими настройками.

## Форма заявок

Работает в двух слоях:
- на хостинге с PHP форма отправляет заявку на `send.php` (проверка Origin, honeypot, лимит 3 заявки за 10 минут с одного адреса, очистка полей, защита от подмены заголовков письма);
- если PHP недоступен (Netlify, GitHub Pages, ошибка сети), форма сама открывает письмо в почтовой программе (`mailto:`).

Настройка на сервере:
1. Скопируйте `send.config.example.php` в `send.config.php` и заполните почту получателя и случайную соль.
2. Если сайт стоит за прокси или CDN, заполните `allowed_hosts` (иначе все заявки получат 403).
3. Проверьте, что `send.config.php` не отдаётся по HTTP (`.htaccess` закрывает его; для nginx нужны правила, они есть в `STATUS.md`).

Не проверялась реальная доставка письма (SPF/DKIM, спам). После публикации отправьте тестовую заявку.

## Выкладка

```bash
sh tools/package.sh            # release/ferz-site/ и zip: Apache + PHP, обычный хостинг
sh tools/package.sh --min      # то же, но CSS и JS минифицированы (нужен Node.js)
sh tools/package.sh --static   # для Netlify / Cloudflare Pages / хостинга без PHP
```

В пакет входят только файлы сайта. Не выкладывайте `.git`, `STATUS.md`, `ANALYTICS.md`, `tools/`, `send.config.example.php`.

Если после выкладки на Apache весь сайт отдаёт ошибку 500, хостинг ограничивает директивы в `.htaccess`. Начало файла описывает, что удалить в каждом случае по тексту из error_log.

Рекомендации хостингу: HTTPS (потом раскомментировать HSTS в `.htaccess`), gzip или brotli включены. Для nginx готовые строки заголовков лежат в `STATUS.md`.

## Как менять

**Цвета и сезоны.** Блок `[data-season="autumn"]` в начале `css/main.css`: цвета строятся из нескольких чисел. Там же закомментированные примеры зимы, весны и лета. Для нового сезона поменяйте этот блок, а также `favicon.svg`, `apple-touch-icon.png` и `og-image.jpg` вручную: они пока не следуют за палитрой.

**Тексты и цены.** `index.html`, по порядку разделов: услуги и цены, как работаю, работы, стек, вопросы, контакт.

**Скриншоты работ.** Исходники (PNG или JPG, лучше шириной от 1600 px) лежат вне сайта, в `src-images/<работа>/` — например, `src-images/ai-travel/01.png`, `02.png`, `03.png`; порядок кадров — по имени файла. В `assets/` их не кладите: на сайт идут только сжатые копии.
1. Положите или замените файлы в `src-images/<работа>/` (имя папки — латиница, цифры, дефис).
2. Выполните `sh tools/images.sh` (все работы) или `sh tools/images.sh ai-travel` (одну). Нужен Node.js: скрипт через `npx` берёт конвертер `sharp-cli` фиксированной версии, в проект ничего не ставится. Для каждого кадра появятся `assets/works/<работа>/01-800` и `01-1600` в форматах `.avif`, `.webp` и `.jpg`, а скрипт напечатает их размеры.
3. В `index.html` в блоке `<div class="… shot--slides" data-slides>` у каждого кадра — `<picture class="slide">`: пути к файлам, `width`/`height` у `<img>` (размеры 1600-й версии из вывода скрипта) и `alt` («Скриншот <проект>: что на экране»). Новый кадр — ещё один `<picture class="slide" aria-hidden="true">` по образцу; первый кадр — без `aria-hidden`, с классом `is-active`.
4. Пересоберите пакет: `sh tools/package.sh`. В пакет попадают только `assets/works/**/*.avif|webp|jpg`, папка `src-images/` — нет (скрипт это проверяет; на Apache `.htaccess` её ещё и закрывает).

Слайдер сам меняет кадр раз в 5 секунд, пока карточка на экране и вкладка активна; без JS и при «уменьшить движение» виден первый кадр. Кнопок у него нет — так решил заказчик.

**Портрет на первом экране.** Оригинал фото лежит в `src-images/portrait/` — эта папка в `.gitignore` и в пакет выкладки не попадает (в фото с телефона есть EXIF и координаты GPS). На сайт идут только готовые вырезки из `assets/portrait/`, без метаданных. Заменить фото:
1. Положите новое фото в `src-images/portrait/` (HEIC, JPG или PNG; человек в полный рост или хотя бы по пояс, лицо в фокусе), старое оттуда уберите — скрипт берёт первый файл по имени. Или передайте путь: `sh tools/portrait.sh ~/Desktop/фото.heic`.
2. Выполните `sh tools/portrait.sh`. Нужен Mac (macOS 14+) с Xcode Command Line Tools (`xcode-select --install`) и `brew install webp libavif`. Всё делается на компьютере, фото никуда не отправляется: фон вырезает встроенный Apple Vision, скрипт доводит край (убирает мусор маски и ореол старого фона, сглаживает), переводит в ч/б с аккуратной кривой и режет два кадра: «по пояс» (`portrait-waist-480|960`, экраны шире 600 px) и «по грудь» (`portrait-chest-360|720`, телефон), каждый в AVIF, WebP и PNG с прозрачностью. В конце печатаются размеры и вес.
3. Посмотрите результат на сайте в светлой и тёмной теме. Если кадр лёг неудачно (другая поза или другое расстояние до камеры), поправьте доли в начале `tools/portrait.sh` (`WAIST_BOTTOM` — линия обреза «по пояс», `CHEST_BOTTOM` — «по грудь», доли высоты фото; `*_HEAD` — запас над макушкой; `CX` — центр по горизонтали) или задайте их при запуске: `WAIST_BOTTOM=0.8 sh tools/portrait.sh`.
4. Если пропорции кадров изменились, поправьте `width`/`height` у `<source>` и `<img>` портрета в `index.html` (скрипт печатает размеры). Пересоберите пакет: `sh tools/package.sh`.

Края волос на светлом фоне Vision иногда оставляет мягкими; если на новом фото заметен ореол, его проще убрать в редакторе на исходнике (или выбрать фото на более ровном фоне), чем подбирать параметры.

**Аналитика.** Выкл. по умолчанию. Выбор сервиса и строки для подключения: `ANALYTICS.md`.

## Что проверено, а что нет

Проверено в Chromium: консоль и CSP, контраст, axe, клавиатура, без JS, reduced-motion, крупный шрифт, Lighthouse Mobile 100/100/100/100, форма с PHP 8.3 и системный Apache 2.4. Подробности и числа в `STATUS.md`.

Не проверялось: Safari, iOS, Firefox, скринридеры, PHP 7.4, nginx, brotli, настоящий HTTPS, реальная доставка писем, открытие `mailto:` в почтовых программах.
